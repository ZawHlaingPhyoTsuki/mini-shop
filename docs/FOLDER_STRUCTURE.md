# Folder Structure

What each folder in this repository is for, and where new code belongs.

## At a glance

```
mini-shop/
├── prisma/                # Database schema and migrations
├── src/
│   ├── components/        # React UI
│   ├── domain/            # Cross-feature business rules and shared schemas
│   ├── features/          # Feature modules (components, server, rules)
│   ├── functions/         # Cross-feature server functions
│   ├── hooks/             # React hooks
│   ├── lib/               # Infrastructure helpers (auth, storage, utils)
│   ├── middleware/        # Request pipeline middleware
│   ├── routes/            # File-based routes and API handlers
│   ├── styles/            # Global CSS and design tokens
│   ├── env.ts             # Generated by Varlock
│   ├── router.tsx         # Router setup
│   └── services.ts        # Shared server instances (db, auth)
├── docs/                  # Product, architecture, and delivery docs
└── .github/workflows/     # CI
```

## `prisma/`

The database source of truth.

| Path            | Purpose                                              |
| --------------- | ---------------------------------------------------- |
| `schema.prisma` | Application models plus the generator block          |
| `auth.prisma`   | Better Auth models, generated by the Better Auth CLI |

Regenerate the auth models with `bun run auth:generate`, then re-apply the
hand tweaks listed at the top of `prisma/auth.prisma`.

No `migrations/` directory is kept during the current phase; apply schema
changes with `prisma db push`. Add versioned migrations before deployment.

## `src/domain/`

**Framework-free business rules and shared schemas.** Nothing in here imports
React, the database, or the network, so it can be unit-tested in milliseconds
and reused on both the server and the client.

| Path                   | Purpose                                                    |
| ---------------------- | ---------------------------------------------------------- |
| `shared/locale.ts`     | Supported locales, localized-name schema, English fallback |
| `shared/money.ts`      | Currency list, whole-unit money schema, formatting         |
| `shared/validation.ts` | Slug and quantity schemas                                  |
| `orders/status.ts`     | Fulfillment and payment statuses plus allowed transitions  |

Use this folder for rules shared across features: what a valid price is, how a
name falls back. Feature-specific rules belong in `src/features/<name>`.
Anything that talks to Postgres, S3, or the session belongs in `src/lib`.

## `src/features/`

Feature-first modules. A feature owns its UI, server functions, schemas, and
rules so a change stays in one place. Routes compose features and stay thin.

```
src/features/shops/
├── components/            # Feature UI (shop form, status card, review list)
├── schema.ts              # Shop input and review-decision schemas
├── server.ts              # Shop server functions
└── status.test.ts         # Shop status rules and tests
```

Add a sibling folder per domain (`features/catalog`, `features/orders`) instead
of growing `src/components` or `src/functions` with feature-specific code.
Import directly (`@/features/shops/server`); do not add barrel files.

## `src/lib/`

Infrastructure helpers that wrap an external system.

| Path             | Purpose                                              |
| ---------------- | ---------------------------------------------------- |
| `auth.ts`        | Better Auth instance (Prisma adapter, allowed hosts) |
| `auth-client.ts` | Browser-side Better Auth client                      |
| `authz.ts`       | Session, global-role, and shop-ownership guards      |
| `prisma.ts`      | Prisma client on the `pg` driver adapter             |
| `storage.ts`     | Neon Object Storage: presigned uploads, stat, delete |
| `utils.ts`       | Small shared utilities (class name helper)           |

## `src/routes/`

File-based routes for TanStack Router.

- `index.tsx`, `login.tsx`, `_auth/` — pages and layouts.
- `api/` — HTTP handlers that are not pages (`api/assets.ts`).
- `__root.tsx` — document shell, 404 and error boundaries.

## `src/functions/`

Cross-feature server functions callable from the client (`get-my-asset.ts`,
`get-user.ts`, `products.ts`). Feature-specific server functions live in
`src/features/<name>/server.ts`.

## `src/middleware/`

Request pipeline middleware. `auth.ts` resolves the session once per request
and exposes it in the server context.

## `src/components/`

React UI shared across features. `ui/` holds the shadcn/ui primitives; feature
UI lives in `src/features/<name>/components`, while cross-feature app components
(header, auth forms, avatar card) stay here.

## `src/hooks/`

React hooks shared by components.

## `src/styles/`

Global CSS and design tokens.

## Root-level files

| File               | Purpose                                                        |
| ------------------ | -------------------------------------------------------------- |
| `prisma.config.ts` | Prisma CLI configuration (schema path, migrations, datasource) |
| `neon.ts`          | Neon infrastructure as code (branches, bucket)                 |
| `vite.config.ts`   | Vite build configuration                                       |
| `vitest.config.ts` | Test runner configuration                                      |
| `.env.schema`      | Environment contract; Varlock generates `src/env.ts` from it   |
| `components.json`  | shadcn/ui registry configuration                               |

## Placement rules

1. Feature-specific code goes in `src/features/<name>` (components, server,
   schemas, rules). Routes only compose features.
2. A rule shared by multiple features goes in `src/domain`.
3. Code that wraps an external system goes in `src/lib`.
4. Anything that reads or writes the database goes through the Prisma client;
   no raw SQL in routes or components.
5. HTTP endpoints live in `src/routes/api`; page routes in `src/routes`.
6. Cross-feature server functions live in `src/functions`.
7. `src/env.ts` and `src/generated/` are generated; never edit them by hand.
